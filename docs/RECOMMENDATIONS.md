# FDN v9.01: Recommendations

Short list, highest value first. IDs (B#, D#, P#) refer to FDN_v9_ANALYSIS.md.

1. **Work in a sandbox save, never your main game.** Use a custom or cheat start (the Script Editor is unlocked by renaming the pilot to `Thereshallbewings`). Keep a "baseline" save from v8.04 and reload it after every compile. Running scripts keep their old version, so after recompiling, reload the save or wait until `is new script version available` triggers.
2. **Git: one branch per phase, one commit per script, one tag per phase** (`v9-phase0` … `v9.01`). Commit the readable source (`src_readable/`) next to the XML so diffs are readable. The XML codearray itself is never edited by hand.
3. **One prompt per script for the local AI.** With 80k context, paste MASTER + REFERENCE + one phase file + the 1–3 scripts for the current step (readable form ≈ 1–4k tokens each). Never paste raw XML (about 10× larger). Start a new chat per step, and keep the AI's answers in `notes/` so it doesn't need history.
4. **Turn the debug log into a feature.** Use one `lib.LI.FDN.Log` that writes to log file 9910 (`log09910.txt`), with levels from the config menu (Off / Errors / Trace). Ask the AI to add a log line at every decision point. This is how you test without a debugger.
5. **R-T1 (decided by Matt): keep the temporary docked trade drone and make it robust (B15).** Why it exists: X3 MSCI has no station-to-station trade command, so a docked ship's `buy`/`sell` is the only way to use the game's own trade mechanics (real price, homebase account, NPC stock, possibly trade rank and stats). Correction to the earlier note: the drone is created already docked and destroyed in the same instant, so freight was never visible and the "feel" doesn't depend on it. v9 moves it into one helper, `lib.LI.FDN.Trade` (REFERENCE §G): pre-spawn checks (partner, foe, sector, price, stock/demand, money), runtime ship-type resolution for XRM/TShips mods, a null-checked create, a wait-free create→destruct with one exit label, an orphan sweep at init, a trade cap and per-ware guard, reconciled records, and logging at each decision. Direct transfer is **not** planned. Treat it only as a possible later config option if the Phase 0 test shows that drone trades don't affect trade rank or stats.
6. **Behaviour changes need your sign-off.** These are B5 (default dock surplus → DC: currently ON for every dock), B9 (reset scope), DC confirmation, and excluding FL Station-Manager stations. The prompts mark them "Behaviour changes (need approval)". Decide once and record the decision in CHANGELOG.
7. **Keep save compatibility rigid:** the script names `al.LI.FDN.event`, `al.plugin.LI.FDN.register` and `plugin.LI.FDN.Main.Menu`; settings indices 0–11; local names `FDN.Ware.%s` and `FDN.Settings`; text page 9910. Removed scripts become **stubs** (return null) for at least one version, so old running tasks or saved references don't error. Leave `lib.BW.isAP` (Bullwinkle's library, shared with other mods) untouched and add `lib.LI.FDN.Game` instead.
8. **Naming prefix:** `lib.LI.FDN.*` for wait-free helpers, `plugin.LI.FDN.*` for tasks and menus, and global keys `LI.FDN.*`. Every new text ID goes on page 9910 in the documented ranges (300–399 text, 4100–4199 keys, 9100–9199 formats).
9. **Text page registration:** 9910 is in the community "free" range but not registered. Before release, check the community text-ID list thread on the Egosoft forum (search "X3 text page ID registry") and claim 9910 (plus 9911–9915 if you want room for future versions). Add `9910-L049.xml` (German) and optionally L033/L039/L007 copies of the English file so non-English FL installs don't show ReadText errors.
10. **Menu access without dependencies:** keep the Community Plugin Configuration entry (most players have it), but always register a hotkey ("FDN Menu") as a fallback (B6). On FL with the Unofficial Patch, also add a script-selection/sidebar entry behind a feature check.
11. **Compatibility notes for the readme:** AP 3.3 and FL 1.3 (+ Unofficial Patch 1.3.20) are supported. TC is not (v8.04 already needed AP; supporting TC would mean keeping the dead TC menus). XRM is OK. LU is incompatible with Plugin Manager-installed scripts and the Bonus Pack, so flag it "untested / unsupported". SRM is unknown, so ask testers. Also mention FL's native Station Manager / Trade Distribution: don't let both manage the same station.
12. **Package with Plugin Manager 1.92 (.spk)** plus a plain zip. Include an uninstall that runs the AL "stop" (removes the config entry and hotkey, clears `[0]`). Refresh the forum thread with a v9.01 changelog and the requirements list.
13. **Tooling:** use X-Studio 1.08 for AP and XScript 0.8 (with the VS Code extension) for FL, if the Phase 0 round-trip passes. Exscriptor (used for v8.04) is obsolete. Don't trust any command the local AI "remembers": every new command must exist in v8.04's source, the MSCI command list, or the in-game editor (the prompts enforce VERIFY tags).
14. **Later (v9.1+), not now:** per-ware min/max via a config page; statistics view; an X4 port should be a redesign (MD/Lua), not a translation, so keep the FDN data model documented in REFERENCE as the spec for it.
