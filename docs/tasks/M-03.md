## Excerpts

### Decisions (DESIGN_v9_direction.md item 2 and 'Decisions 2026-10-28'; notes/M-02.md accepted by Matt 28/10/2026)
- Each factory and dock is served by the **closest DC whose station range covers it** (its home DC). Tie: the larger range, then the older DC (lower position in the DC list [30]).
- **Out of range = not served.** Scan logs an out-of-range station once (P2-14 format) and keeps its records untouched.
- Station range `R = R_base + type modifier`, minimum 1. `R_base` = settings [32] (default 3). Modifier: Player HQ +2, Trading Station +1, Equipment Dock 0, any other dock -1. A per-DC override `FDN.DC.Cfg`[0] (an INT of 1 or more) replaces the computed value.
- DC type is read from the station **subtype** (Equipment Dock = 6, Player HQ = 62, both seen in the M-01 probe on FL) and NOT from the SS_DOCK_P_* constants. The Trading Station subtype has not been seen yet: treat it as 'other dock' (-1) until the probe shows it, and log the subtype of every DC once so Matt can report it.
- The range check is used only when settings [31] = 1. When [31] = 0 the closest DC serves every station (no range limit).
- Backbone: two DCs are linked when their jump distance is within `R_bb = 2 x R` of BOTH DCs (use the smaller of the two). Routes between DCs use the fewest total jumps over links, never revisit a DC, safety cap 16 hops. The route table is cached in settings [35] and rebuilt by Scan.

### Station locals (M-02 section 3)
- `FDN.Hub` on a factory or dock: array of 3: [0] home DC (null = out of range), [1] jumps to it (-1 when out of range), [2] stamp (the playing time of the Scan that wrote it).
- `FDN.DC.Cfg` on a DC: array of 4: [0] range override (-1 or null = use the type value), [1] floor percent override (not used here), [2]-[3] reserved. M-03 only READS it.

## Key facts

- Commands confirmed in game (M-01 probe on FL 28/10/2026) and in FDN sources: `$j = = get jumps from sector $a to sector $b` (same sector = 0), `$sec = $station -> get sector`, `$st = $station -> get subtype`, `$st -> get local variable: name=...`, `$st -> set local variable: name=... value=...`, `size of array`, `array alloc: size=`, `append ... to array`, `remove element from array ... at index`. Use nothing else; any other command needs `VERIFY:` and a stop.
- VERIFY item: what `get jumps from sector` returns for an unreachable sector (the probe logged null for a null sector). Treat any non-INT or negative result as 'unreachable'.
- Settings are read with `$al.Settings = [THIS] -> call script lib.LI.FDN.Cfg.Get :` (the shared array or null). The array has 30 entries until this card; every new script must check `size of array` >= 40 before reading [30]-[39] and return null (or do nothing) below that.
- DC validity: `lib.LI.FDN.Is.Valid : obj=$dc need.dock=[TRUE]`.
- Logging: `= [THIS] -> call script lib.LI.FDN.Log : text=$txt.log caller=$script.name` (only writes when debug [7] is on).
- House style (Matt's rules, always): a discarded call result is written ` = [THIS] -> call script ...` (leading space-equals), never `$null =`. No AND, OR, && or || (nest `if` blocks). No `!=` (use `if not $a == $b`). No array element inside a condition (copy it to a local first). No `->` or calls inside a condition (assign first, then test the variable). `null == null` is FALSE, so test with `is datatyp[ $x ] == DATATYPE_NULL`. No arithmetic inside `array alloc: size=` (compute the size into a local first). Block balance: `if` lines (not counting `else if`) plus `while` lines must equal `end` lines. `return` inside a gosub sub ends the whole script: leave a sub with `endsub` only.
- Every new or changed file: CRLF line endings, ASCII only, header in the usual form (`* Script:`, `* Desc:`, `* Arg n:` lines, Version, Date, `* Tested: not tested`) and a change tag line ` * v9.01 D6 (M-03): ...`. New scripts start at version 1.0.
- Edit rules: use only your normal file tools. No `python -c`, PowerShell or other shell command on any source file. Never edit `lib.BW.isAP`. Keep every existing text ID unchanged. New player-visible strings only in 9910 ids 300-399, and only listed in your notes (Matt adds them to 9910-L044.xml himself). Local variable names are literal strings in this card ('FDN.Hub', 'FDN.DC.Cfg'), not text ids. If something fails, stop and tell Matt exactly what failed; do not retry in a loop.
