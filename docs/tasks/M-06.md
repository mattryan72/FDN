## Excerpts

### Decisions already in place (DESIGN_v9_direction.md 'Decisions 2026-10-28'; notes/M-02.md; M-03)
- `[2]` stays the **primary DC**; `[30]` is the DC list and always holds `[2]` as element 0 (`lib.LI.FDN.Dc.List` cleans it: valid Docks only, `[2]` first, no duplicates, writes the cleaned array back).
- `plugin.LI.FDN.DC.Change` (args old, new; returns 'ok', 'busy', 'invalid', 'same', 'fl.managed') is the **only writer of [2]** besides Setup. It takes the global run lock (settings [12], `lib.LI.FDN.Lock` key=12 action='try'/'release'), creates ware records on the new DC, copies the DC policy fields, keeps both stations in the dock array [4]. It does NOT touch [30]: after a change the old primary is still in [30], so Dc.List keeps it as a secondary DC.
- `lib.LI.FDN.Dc.Range : dc=` -> INT range (override `FDN.DC.Cfg`[0] when INT >= 1, else R_base [32] + subtype modifier: HQ 62 +2, Equipment Dock 6 0, other -1; minimum 1).
- `lib.LI.FDN.Route.Build :` -> link count; rebuilds [35] from Dc.List. Wait-free.
- `lib.LI.FDN.Hub.Assign : station=` -> home DC; writes `FDN.Hub` = [home DC or null, jumps or -1, playing time]. Wait-free. A DC is its own home with 0 jumps.
- `plugin.LI.FDN.Scan` is a task (it waits). It is started by Supply.Start when [16] is older than [17] seconds or not an INT; at its end it runs Route.Build and Hub.Assign for every factory and dock. A menu must never call Scan synchronously; it forces a rescan by writing `$al.Settings[16] = null`.
- `FDN.Cost` on a DC, factory or dock: [0] total EC, [1] transfer count, [2] playing time of the first charge, [3] deferred EC. Nothing calls Cost.Pay yet (that is M-05), so all running-cost values are 0 or missing until M-05 is in.

### Menu structure today (plugin.LI.FDN.Main.Menu)
- Stack of [view, obj, ware]. Views: 1 DC (Menu.Station view=1), 2 Stations (Menu.Stations), 4 Factory details, 5 Dock (Menu.Station view=5), 6 Ware details, 7 Config. **View 3 is free.** Build.View.Sub picks the builder; Updater.Sub starts Menu.Refresh only for views 1 and 5.
- Menu.Command returns the new stack. Navigation: `open.dc` forces obj = [2]; `open.stations`, `open.factory`, `open.dock`, `open.ware`, `open.config`, `back`. `set.dc` (Set.DC.Sub, L634-669): Is.Valid, one Boolean confirm (text 351) when a DC exists, DC.Change, 'busy' -> logbook text 352, then Reg.Add and the stack restarts on view 1.
- Config.Menu: with no valid DC it lists every valid player Dock as 'set.dc' rows (heading 123); with a DC it shows the DC (ObjLine) and the change-DC list (heading 124).
- Menu.Stations drops only `[2]` from the dock list, so secondary DCs appear as ordinary docks today.
- Row libraries: `lib.LI.FDN.Menu.Row : menu label value retval` (retval null = info line), `lib.LI.FDN.Menu.Toggle : menu label bool retval`, `lib.LI.FDN.Menu.ObjLine : menu object`, `plugin.LI.FDN.Format.Name : object`.
- There is no `lib.LI.FDN.Cfg.Set`; every writer does `set global variable: name='al.LI.FDN.event' value=$al.Settings` itself.

### Proposed design
- New view **3 = DC list** (new builder `plugin.LI.FDN.Menu.DC.List`). `open.dc` with no station obj, and the DC page entry from the Stations/Config views, go to view 3. Main.Menu starts on view 1 (the primary DC) when [30] has one DC, and on view 3 (the DC list) when it has two or more (DECIDED Q6.5).
- Per DC in Dc.List order, one block:
  - ObjLine (name [ID] + sector), plus 'Primary' (text 357) on element 0.
  - Info line text 362: `<type> | range <R> | stations <n> | EC <total> (<per hour>/h)`. Type is from `get subtype` (62 -> 358, 6 -> 359, anything else -> 361; 360 is ready for the Trading Station once its subtype is known). R from Dc.Range. n = number of stations in [3] and [4] whose `FDN.Hub`[0] is this DC (copy the element to a local before comparing; the DC itself does not count). EC from `FDN.Cost`[0]; the per-hour figure uses the M-07 rate rule. Until M-07 is in, show the total only.
  - Rows: Open (returns ['open.dc', dc] -> view 1 with that DC), Make primary (['dc.primary', dc], not on element 0), Remove (['dc.remove', dc]).
- Heading 'Add Distribution Centre' (354): every valid player Dock (`Is.Valid` need.dock TRUE) that is not in [30] and not FL-managed, as ['dc.add', dock] rows (same loop as Config.Menu Dock.List.Sub). Hidden when [30] already has 16 DCs (DECIDED Q6.1: maximum 16).
- **Add DC:** confirm (363), then `lib.LI.FDN.Dc.Edit : action='add' dc=`. With no DC set at all, Add goes through the existing `set.dc` path instead (DC.Change creates the records and writes [2]); Dc.Edit then puts it in [30]. PROPOSED (Q6.2): a secondary DC added later gets no copied records; Ware.Rec creates them on demand.
- **Remove DC:** refused with 365 when it is the only DC. Confirm (364). When the DC is the primary, first call `plugin.LI.FDN.DC.Change : old=[2] new=<next DC in [30]>` (it owns [2] and the records); only when that returns 'ok' call Dc.Edit 'remove'. The removed station stays in the dock array [4] as an ordinary dock; DECIDED (Q6.3): keep everything on the removed DC - ware records, virtual stock and FDN.Cost stay untouched.
- **Make primary:** confirm (368), then DC.Change old=[2] new=dc. Because DC.Change does not touch [30], the old primary stays a secondary DC (this replaces 'Change DC'; the old 'Change DC' list in Config.Menu goes away). DECIDED Q6.4: there is NO one-step Replace DC; the player uses Add, Make primary and Remove.
- **After every change:** Dc.Edit (and the Make primary handler) call Dc.List, then Route.Build, then Hub.Assign for every station in [3] and [4] (all wait-free), and set [16] = null so the next Supply.Start runs a full Scan. The handler then rebuilds the stack as [view 3].
- **Lock:** Dc.Edit takes the same lock as DC.Change (key 12, action 'try'); a held lock returns 'busy' and the menu writes text 352 to the logbook. In the Remove-primary case DC.Change takes and releases the lock first, then Dc.Edit takes it again (nothing waits in between, so no supply pass can run in the gap).

## Key facts

- Commands confirmed in game and in FDN sources: `get station array: of race Player class/type=Dock 2007`, `$st -> get subtype`, `$st -> get sector`, `$st -> get local variable: name=...`, `size of array`, `array alloc: size=`, `append ... to array`, `remove element from array ... at index`, `find ... in array:`, `get user input: type=Var/Boolean, title=`, `write to player logbook`, `add custom menu heading/info line/item to array`. Anything else: `VERIFY:` and stop.
- Settings are read with `$al.Settings = [THIS] -> call script lib.LI.FDN.Cfg.Get :`; check `size of array` >= 40 before touching [30]-[39].
- House rules (always): discarded call results are written ` = [THIS] -> call script ...`, never `$null =`. No AND, OR, && or || (nest `if`). No `!=` (`if not $a == $b`). No array element, `->` or call inside a condition or a string expression (copy to a local first). `null == null` is FALSE (test with `is datatyp[ $x ] == DATATYPE_NULL`). Arrays with `= = array alloc: size=N` (size in a local, no arithmetic); time with `= = playing time`. Loops count with `inc $i =` or `dec $s =` (never `$i++`, the compiler drops it). No `break`, no `continue`. No `return` inside a gosub sub (`endsub` only). Block balance: `if` (not `else if`) + `while` = `end`.
- Every new or changed file: CRLF, ASCII, no BOM; header (`* Script:`, `* Desc:`, `* Arg n:`, Version, Date, `* Tested: not tested`) and a tag line ` * v9.01 D6 (M-06): ...`. New scripts start at version 1.0.
- Edit rules: only your normal file tools; no `python -c`, PowerShell or shell commands on any source file; never edit `lib.BW.isAP`; keep every existing text id; new strings only from the approved table above (Matt adds them to 9910-L044.xml). Stop and report on any failure; do not retry in a loop.
