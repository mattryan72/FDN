# Card P2-11b - plugin.LI.FDN.Sell.Ware on the shared libraries

Status: tested TC 26/10/2026 (guard paths only). Closes D1, D2 (one of nine), B4, B12, B15; owns counter [18] for sells. The trade guard FDN.Trade.<ware> is taken by Supply.Dock before this script STARTs - Sell.Ware only releases it at Exit:.

## What it does
The sell half of the dock pass - Supply.Dock (P2-10b) STARTs this script when a dock holds stock above its sell cap for a ware, after taking Lock : obj=$dock key='FDN.Trade.' + $ware action='try' timeout=120 and NOT releasing it:

1. Standard header via lib.LI.FDN.Cfg.Get (D1). `$counter.inc = [FALSE]` and `$trade.key` are both set before the Cfg.Get call so a settings failure still exits cleanly through Exit: with the guard key known.
2. Guard chain, all ending in goto label Exit: with one log line each when debug is on:
   - $trade.key = FDN.Trade.<ware> built first (only when $ware is not null) so Exit: always knows whether to release the caller's guard.
   - Is.Valid : obj=$dock need.dock=[TRUE], then Is.Valid : obj=$dc need.dock=[TRUE] (B12).
   - Ware.Rec : station=$dock ware=$ware create=[FALSE] (D3); a null record skips this sell.
   - $sell.cap = rec[5] must be an INT >= 0 (-1 = selling off) and $sell.at = rec[6] must be an INT (B4).
3. Task cap: fresh reads of [18]/[19], nested INT checks mirroring Buy.Ware v3 and the Supply.Dock sell gate - non-INT or max <= 0 = unlimited; only while active < max does it increment [18], save, and set $counter.inc = [TRUE]. A cap hit logs "Sell skipped - trade task cap reached (a/b)" and exits. A non-INT [18] is counted from 0 before the increment.
4. Sector search: lib.LI.FDN.Sectors : mode=3 (cache only, no scan); a null list skips this pass. Loop while $s > 0 / dec $s =; each pass re-reads the record via Ware.Rec(create=[FALSE]), re-checks [5], and recomputes amount = rec[0] + physical stock - [5] (the amount from Supply.Dock is only a hint). The v8 find command (resource, best price min.price=sell.at, max.jumps=0, startsector, exclude array) is unchanged.
5. Per found buyer: ONE wait-free lib.LI.FDN.Trade : mode=sell partner=$sell.Station ware=$ware amount=$amount home=$dock (B15 - hardened drone inside Trade; sell mode already removes the sold units from dock stock and stamps rec[8], so no Update.Ware remove call here). A non-INT result is floored to 0; $traded > 0 decrements $amount and logs "Sold N of ware at station".
6. Between passes: wait randomly from 500 to 1000 ms and re-validate dock + DC with Is.Valid after every pass while $more; a sector with no buyer does NOT set $more = [FALSE] (only the "enough sold" or "nothing left above cap" paths do), so it still waits and re-validates like v8. Only the final pass - when amount is filled or nothing remains above the cap - skips them. Either Is.Valid failure logs "Sell stopped - ..." and exits at the single label. No continue, no extra dec, $skip/$more flags only.
7. After the loop: if $amount > 0 log "No buyer found for remaining N of ware".
8. Single Exit: label (14 gotos): null out $trade.key unless the dock is a station (is datatyp[ $dock ] == DATATYPE_STATION), release the guard when $ware and $trade.key are set, decrement [18] if incremented (re-read settings via Cfg.Get first; floor at 0 so a stale counter can never go negative) and save, then return null.

## Test steps
1. Dock with a ware above its sell cap and a realistic sell-at price [6]; an NPC buyer in a cached trade sector at or above that price. Expected: Supply.Dock logs "Sell cap N, stock M, selling K of <ware>", STARTs Sell.Ware, which increments [18] and walks the sectors; per found buyer one "Sold X of <ware> at <station>" line and the dock's physical/virtual stock drops accordingly (rec[8] stamped). On Exit: [18] is back where it started and the dock local FDN.Busy.FDN.Trade.<ware> is null.
2. Force two wares over cap on the same dock in one pass with [19]=1: first sell runs, second logs "Sell skipped - trade task cap reached (1/1)"; [18] never exceeds 1 and returns to its start value when both tasks finish.
3. Destroy/sell the dock mid-run - after the wait, "Sell stopped - dock no longer valid", Exit: releases nothing on the destroyed dock (Lock returns null) and decrements [18]. Same for a sold DC with "Sell stopped - DC no longer valid".
4. Ware over cap but no NPC buyer anywhere above the sell-at price: one "No buyer found for remaining N of <ware>"; no stock change, lock released, counter back to start.

## Result (TC 26/10/2026)
In game on TC the test script gave: null dock exits with [18] unchanged; an NPC dock with the lock taken exits with "dock no longer valid" and the lock released; a ware with sell cap off exits with "sell cap off", [18] still null and the lock released. [18]/[19]/[7] restored after all runs.
Not exercised live: the task-cap check (no ware with a valid sell record was available), a real [18] increment from null and its decrement at Exit:, and a real sale through lib.LI.FDN.Trade - check the log on a natural Supply.Dock pass when a dock holds stock above its sell cap.
