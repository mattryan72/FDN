# P3-09 - plugin.LI.FDN.Menu.Refresh (single live updater)

Status: written by Cline, one fix by me (a stray $s.name = get script name line removed); not yet tested in game.

## What changed
- New task plugin.LI.FDN.Menu.Refresh (view, obj, token) replaces plugin.LI.FDN.Menu.DC.Details_D and Menu.Dock.Details_D.
- It does not build rows. Menu.Station draws the first rows and stores each ware row pair [row, retval] in the global named by text 5000 (id, ware) and the credits row in the global named by text 5001 (id). Refresh asks lib.LI.FDN.Menu.WareRow for a fresh pair and copies the new row's elements into the stored row array, which is the same object the open menu holds.
- It returns at once for a static view (settings [6][0] for the DC, [6][2] for a dock). While running it exits when settings are gone, FDN is off ([0]), the token [20] differs from its token argument, settings [5] differs from its view, or the station no longer exists.
- Main.Menu: Updater.Sub now STARTs Menu.Refresh (view, obj, token) instead of the two _D scripts, still only when it enters view 1 or 5 or a different station. Header comments updated.
- Wares added after the draw have no stored row and are skipped until the next redraw.

## Not changed
- The two _D scripts stay in the repo for now (unused); P3-10 retires them.
- The command 'is new script version available' from the card is not used (never verified in this project).
