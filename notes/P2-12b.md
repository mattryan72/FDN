P2-12b: Move.Ware on the shared libraries
=========================================

Closes
------
D1, D2 (one of nine), D3, B3/B12 source check. B20 kept.

What changed
------------
- Header switched to lib.LI.FDN.Cfg.Get ($PageID comes from $al.Settings[1]).
- Debug.Sub deleted; every debug line goes through lib.LI.FDN.Log with $s.name as caller.
- Source validated up front with lib.LI.FDN.Is.Valid : obj=$source need.dock=[FALSE], and again after the prompts before anything moves.
- The source ware record is read via lib.LI.FDN.Ware.Rec (create=[FALSE]) inside Source.Stock.Sub, so it is fresh after the prompts; no text 4000 sprintf, no null-array read of [0].
- $destination -> exists re-check added after the amount prompt.
- Destination checks ($dest.is.dock / $dest.free) copied to locals before use in conditions.
- The two duplicate Dock/Ship add/remove blocks merged into one path: add first via plugin.LI.FDN.Update.Ware, then remove what was really added.
- The remove result is now kept and logged instead of discarded.

Behaviour kept
--------------
- All prompts (texts 184, 178) and subtitle texts 192, 193, 194 unchanged.
- Same clamps: amount > stock clamps to stock; add failure exits; destination same as source exits.
- Always returns null.
- Moving into a ship still works: Update.Ware v8 only accepts stations, so a ship destination gets a plain cargo bay add limited to its free space (as v7 did); a station destination goes through Update.Ware. The source is always a station and always goes through Update.Ware.

Behaviour changed
-----------------
- A source with no ware record now counts as virtual stock 0 instead of reading a null array (crash fixed).
- The amount is clamped to a fresh stock read taken after the prompts.
- A gone or invalid source/destination after the prompts exits with a log line before anything moves.
- If less was removed than added, a 'Move mismatch' log line is written - it is never undone.

Kept on purpose
---------------
- The destination is NOT checked with Is.Valid: it only accepts stations and the prompt allows ships, so the destination keeps a plain $destination -> exists check.
- No Exit label needed: no lock or counter to release.

Block count
-----------
34 if + 0 while = 34 end, plus one endsub for Source.Stock.Sub.

Test plan hints
---------------
- Null source: exits with a log line, nothing moves.
- Move 0 (amount not > 0): exits silently after the prompt.
- Move more than stock: amount clamps to what is actually available.
- Move to the same station as the source: subtitle text 192, exit.
- Cancel the destination prompt: exits before any -> call.
- A DC-to-dock move with a small amount and back: net zero in cargo bay and virtual stock.
- A move into a ship: ware lands in the ship cargo bay (plain cargo add, no virtual change on either side).
