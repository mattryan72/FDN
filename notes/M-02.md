# M-02: Storage and upgrade design for multi-DC, range and Energy Cell cost (28/10/2026)

Design only, no code. Based on: docs/DESIGN_v9_direction.md (items 2 and 3 plus the Decisions and Cost formula sections of 28/10/2026), notes/M-01.md (FL probe) and the current settings and ware record layout (docs/FDN_v9_REFERENCE.md).

## 1. Principle: [2] stays the primary DC

19 scripts read `$al.Settings[2]` as "the DC" (Main.Menu, Menu.Command, Scan, Supply.Start, Supply.Dock, Supply.Dock.Check, Supply.Factory, Supply.Factory.Check, Buy.Ware, Sell.Ware, DC.Change, Reset, Upgrade and the menu scripts). To keep all of them working while the multi-DC cards are built, `[2]` keeps meaning "the primary DC" (the DC the player picked first). The full list of DCs is new, in `[30]`, and always contains `[2]` as its first element. Scripts that only need one DC keep reading `[2]`. Scripts that must serve every DC (Scan, Supply.*) switch to the list in M-03 and M-05.

## 2. Settings array: 30 grows to 40

| Slot | Meaning | Default (fresh) | Default (upgraded v8 save) |
|---|---|---|---|
| [30] | DC list: array of DC stations, [0] = the same station as [2] | [ [2] ] | [ [2] ] |
| [31] | Range limit on (1) or off (0) | 1 | 0 |
| [32] | R_base: station range in jumps (the DC type modifies it) | 3 | 3 |
| [33] | Energy Cell cost on (1) or off (0) | 1 | 0 |
| [34] | Global reserve floor percent (layer 3 of the floor) | 25 | 25 |
| [35] | Route table cache: array of [dcA, dcB, jumps] links, rebuilt by Scan | empty | empty |
| [36] | Time of last network Energy Cell check (playing time) | 0 | 0 |
| [37]-[39] | Reserved | null | null |

Indices 0-29 keep their meanings. Upgrade grows the array to 40 (as it grew 12 to 30) and fills [30]-[36] only when empty. Setup.Keys skips below size 30 today; any new setup step must check size 40.

Cost constants (B, J, B_bb, J_bb, the type, tier and DC-type multipliers) are NOT settings. They are literals at the top of the new cost library, so they can be tuned in one place without growing the menu (design principle: avoid options).

## 3. Station locals (new, text ids to add in 4103-4105)

- `FDN.Hub` (text 4103), on a factory or dock: array of 3: [0] home DC (closest DC whose range covers it, or null = out of range), [1] jumps to it, [2] stamp (the Scan time it was set). Written by Scan, read by Supply.
- `FDN.Cost` (text 4104), on any DC, factory or dock: array of 4: [0] total Energy Cells charged on transfers touching this station, [1] transfer count, [2] start time (playing time of the first charge), [3] total of deferred transfers. Energy Cells per hour = [0] x 3600 / (now - [2]). A DC adds what it paid; a factory or dock adds the cost of the legs that served it.
- `FDN.DC.Cfg` (text 4105), on a DC: array of 4: [0] range override in jumps (-1/null = use the type value), [1] floor percent override (-1/null = inherit, layer 2), [2]-[3] reserved.
- Ware record `FDN.Ware.<ware>` (size 12): slot [9] is free; it holds the per-ware floor percent (-1/null = inherit, layer 1). Existing records have null there (no migration needed, null means inherit). The P0-A note says [9]-[11] are free.

## 4. Floor, range and priority rules (from the decisions)

- Floor for a ware on a DC = ceil(capacity x pct / 100), pct from the first set layer: ware record [9], then `FDN.DC.Cfg`[1], then settings [34]. The test stock is physical + virtual (M-01 showed virtual far above capacity: 413,161 against 15,000 for Energy Cells on the Equipment Dock).
- Range R = R_base + type modifier (Player HQ +2, Trading Station +1, Equipment Dock 0, other docks -1, minimum 1), unless `FDN.DC.Cfg`[0] is set. Backbone range R_bb = 2 x R, and a link uses the smaller of the two DCs. DC type is read by class text or subtype (Equipment Dock 6, HQ 62), not the SS_DOCK_P_* constants.
- A station is served by the closest DC in whose range it sits; tie: larger range, then the older DC (position in [30]). When [31] = 0 range is ignored: the closest DC serves any station.
- The shortage pull and the Energy Cell network check use the route table [35] (fewest total jumps, safety cap 16 hops).

## 5. Upgrade and fresh install

- Upgrade (every run): grow to 40; fill [30]-[36] when empty; make sure [30][0] is the same as [2] (and drop dead DCs from [30]; if [2] is invalid, keep the existing invalid-DC path).
- Fresh install or first run on a v8 save (only while [14] is not yet 901): if [2] is a valid DC at that moment, the save already has a network, so set [31] = 0 and [33] = 0 (v8 behaviour, the player switches them on). If [2] is not set, it is a fresh install, so [31] = 1 and [33] = 1. (Rule to confirm with Matt.)
- Reset clears [30]-[36] to the fresh defaults and the `FDN.Hub` and `FDN.Cost` locals.
