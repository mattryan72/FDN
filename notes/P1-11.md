# P1-11 - Reset B9 (registry-based reset)

## Assumptions
- Settings `[12]-[20]` are v9 working slots only: [12] supply run-lock, [13] reverse toggle, [14] schema stamp, [16] scan timestamp, [20] updater token. No script outside Reset writes `[15]/[17]/[18]/[19]` (checked by search), so nulling them on Reset is safe.
- The B8 menu updaters (Dock.Details_D / DC.Details_D) also exit via their own `if $al.Settings[0]` FDN-off check, so pausing first ([0] = FALSE) kills stale updaters too - clearing [20] afterwards cannot resurrect them.
- "Wait one tick" is implemented as `= wait 500 ms`, matching the small-wait idiom used elsewhere in FDN; it only needs to be long enough for a running supply task to reach its next `[0]` check (the AL timer ticks every ~25 s).
- The registry `[29]` can hold entries that are no longer in [3]/[4] and stations that have been destroyed - the approved scope explicitly wants those cleared or skipped, not just the current arrays.
- `continue` is spelled without "while" (MSCI_PRIMER lists `break`, `continue`; Upgrade L060/L076 use bare `continue`).

- Step (1): pause FDN - `[0] = [FALSE]`, write global, `= wait 500 ms`.

- Step (4): `[2] = null`, fresh arrays for [3]/[4]/[29], then loop `$i = 12..20` setting each slot to null; single final `set global variable`.
- Clear.Local.Sub: regex changed from `'FDN*'` to anchored `'^FDN\.'` (single backslash, T8 verified); debug line when locals were cleared.
- New standard Debug.Sub block at the end (same as Upgrade/Supply.Factory.Check), writing through `write to log file $DebugID`.

## Test steps
Run with [7] debug ON so `log09910.txt` gets the B9 lines:
1. **Anchored regex / foreign names survive.** On the DC, set via Script Editor: local `FDN.Test = 1`, local `OtherMod.FDThing = 42`. Run Reset from Main Menu > Other. Expected: all `FDN.*` locals on the DC are null; `OtherMod.FDThing` is still 42 (it would have been wiped by the old unanchored `FDN*`).
2. **Registry reach beyond [3]/[4].** Take a dock out of the FDN network earlier in the session (so it left [4] but stays in registry [29]), then Reset. Expected: its `FDN.*` locals are still cleared - this is what v8 could not do.
3. **Destroyed station.** Destroy one managed factory, wait for a scan to prune it from [3] (it remains in [29]). Run Reset. Expected: debug line `B9: skipping destroyed station`, no script error, all other stations still cleared.
4. **Pause first.** With supply running and a Supply task active, run Reset. Expected: within ~1 s the running supply stops at its next `[0]` check; after Reset, [0] = FALSE in `al.LI.FDN.event`, no supply tick fires until FDN is re-enabled and a DC chosen again.
5. **Working slots cleared.** After Reset, inspect `al.LI.FDN.event`: [2] null; [3], [4], [29] empty arrays (size 0); [12]-[20] all null; [7], [14] (= 901) and [28] unchanged.
6. **No re-stamp on load.** Save, reload. Expected: NO `B16: settings schema stamped to 901` line in the log (because [14] was not nulled), no registry re-seed line either ([29] is an empty array, not null).
7. **Re-enable works.** Open FDN menu, enable FDN and pick a DC; supply resumes normally on later ticks.
