# P2-02: lib.LI.FDN.Is.Valid + lib.LI.FDN.Is.Factory (new)

Saved per the task card (`docs/tasks/P2-02_lib_Is.Valid_Is.Factory.md`). Written 22/10/2026, Cline session. Prompt built with `--stamp` (~4,745 tokens).

Test result (TC): both libs first tested against real stations - every call returned null. Cause: TC's `is datatyp[]` returns DATATYPE_STATION for factories, docks and complex hubs, not DATATYPE_OBJECT, so the original datatype guard rejected every real station. Fixed in both libs: guard is now `if not is datatyp[ $obj ] == DATATYPE_STATION` ($station in Is.Factory); comments and header "Returns" text updated to "not a station". Re-test pending after the fix (still marked "not tested" until it passes).

Plan approved by Matt before writing, with these changes:
1. Datatype check first in both libs (`if is datatyp[ $obj ] == DATATYPE_OBJECT`, null on failure) - calling `-> exists` on a number or string can throw a script error. Is.Factory gets the same guard on `$station`.
2. Return `[TRUE]`/`[FALSE]`; null only for bad input (not an object, or it does not exist). A valid existing object that fails ownership/Dock/D10 returns `[FALSE]`, not null.
3. Is.Factory stays owner-blind exactly like Sector.Array; callers needing ownership call Is.Valid first (header comment says so).
4. `is detectable == 0` copied as-is with a one-line D10 mirror note and VERIFY tag - no cloaking guesswork in the code (VERIFY line kept minimal: "intent unconfirmed").
5. Class names exactly as pasted sources use them: `Dock 2007`, `Factory 2006`, `Complex Hub`.

### Script: lib.LI.FDN.Is.Valid + lib.LI.FDN.Is.Factory (new) Task P2-02 (B3, B12, D10)

Test steps (from a test script, FDN initialised):
1. Is.Valid with a player-owned dock, need.dock=[TRUE] -> `[TRUE]`; same dock, need.dock=null -> `[TRUE]`.
2. Is.Valid on the DC (a Dock) with need.dock=[TRUE] -> `[TRUE]`.
3. Is.Valid on a player-owned **factory** with need.dock=[TRUE] -> `[FALSE]` (exists and owned, fails the Dock test); same factory with need.dock=null -> `[TRUE]`.
4. Is.Valid on an NPC dock, need.dock=null -> `[FALSE]` (ownership fail).
5. Is.Valid with `obj=null`, and a plain number -> null each time, **no script error** (datatype guard fires before any `->` call). This is the key new-behaviour check.
6. Pass a destroyed object's ref: null (`-> exists` false), not `[FALSE]`.
7. Is.Factory on each station in Sector.Array's factory list -> `[TRUE]`; on the DC and any non-factory dock -> `[FALSE]`; on an NPC-owned factory (if one can be obtained) -> still answers per D10 alone (owner-blind, no ownership check).
8. Is.Factory with `station=null` / a number -> null each time, no script error.
