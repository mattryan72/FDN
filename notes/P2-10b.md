# Card P2-10b - `plugin.LI.FDN.Supply.Dock` on the shared libraries

Status: Tested TC 25/10/2026. Written 25/10/2026, Cline session.

## What it does
The per-dock supply task (flag = null or 1), now on the Phase 2 shared libraries - same pattern as P2-09b (`Supply.Factory` v3) and P2-10a (`Dock.Check` v3):
1. Header switched to `lib.LI.FDN.Cfg.Get` (D1); `$s.name = $script` taken once for Log calls; `$PageID` / `$DebugID` deleted.
2. The dock is validated up front (return null if invalid). In the flag==1 branch both the dock and the DC are validated. In the dock pass the DC is validated before every DC touch (surplus return and supply). Both are re-checked after every wait (B12/B3) and a failure stops the pass with a debug line.
3. Ware records read via `lib.LI.FDN.Ware.Rec : station=$dock ware=$ware create=[FALSE]` (D3). A null record sets `$skip.ware = [TRUE]` instead of reading null array elements (B4); the DC record is read the same way, only when the DC is valid.
4. All debug through `lib.LI.FDN.Log : text=... caller=$s.name` inside `if $debug.on` blocks (D2). Debug.Sub deleted (one of nine).
5. Skip-flag pattern: `$skip.ware = [TRUE]` replaces early-exit for per-ware failures; the loop continues to the next ware.
6. Fresh cap check (B1/B4): `[18]/[19]` read only inside `if $sell.go`; non-int or max <= 0 treated as unlimited (`$cap.ok` stays TRUE).
7. Lock per dock/ware (B2): `lib.LI.FDN.Lock : obj=$dock key='FDN.Trade.' + $ware action='try' timeout=120`. One block only - cap first, then lock. Local is `FDN.Busy.FDN.Trade.<ware>` (text 4100), held by Sell.Ware on every exit, stale after 120 s.
8. Asynchronous `START plugin.LI.FDN.Sell.Ware : dock=$dock ware=$ware amount=$amount` fired only when cap OK and lock taken (B1/B11). This script never writes `[18]` or releases the lock - Sell.Ware (P2-11b) owns both.

## Out of scope on this card (deliberately untouched)
- Supply.Start's `START Dock.Check` / `START Dock` stay as-is. The sync+Lock switch needs its own card and a lock-key/index decision.
- P2-12a moves the DC 'create' into Ware.Rec; this script still calls Update.Ware 'create' for that path.
- No budget/cursor restructure of the ware loop (docks are few, wares per dock bounded by the settings array).

## Contract for P2-11b (`plugin.LI.FDN.Sell.Ware`)
Supply.Dock only **checks** `[18]/[19]`: skips when both are INT, `[19] > 0`, and `[18] >= [19]`. It never writes either value.

Lock: `lib.LI.FDN.Lock : obj=$dock key='FDN.Trade.' + $ware action='try' timeout=120` (local `FDN.Busy.FDN.Trade.<ware>`, text 4100). Supply.Dock does NOT release it.

Sell.Ware owns `[18]`: increment on start; release that same Lock on every exit; decrement `[18]` on every exit by re-reading the global and saving with `set global variable`.
