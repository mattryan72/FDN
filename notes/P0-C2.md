## 1) `tests/test.LI.FDN.T5.txt` — does a docked TS spawn at an NPC station and pass the drone checks

Full source is in the file (header + 001–054). The load-bearing lines:

```
011  $station = find station: product $ware with best price:  max.price=2000, amount=1000, max.jumps=99, startsector=[PLAYERSHIP], trader=null, exclude array=null
...
018  $drone = = create ship: type=Argon Mercury Super Freighter XL owner=Player addto=$station x=null y=null z=null
019  write to log file 9999 append=[TRUE] value='T5 create ship returned ' + $drone
...
024   $maker.race = $drone  ->  get maker race          * VERIFY (B15)
031  if $drone -> is docking allowed at $station        * VERIFY (B15)
037  if $drone -> can transport ware $ware              * VERIFY (B15)
043  $max.cargo = $drone  ->  get max amount of ware $ware that can be stored in cargo bay   * VERIFY (B15)
047  $drone  ->  destruct: show no explosion=[TRUE]     (Sell.Ware L098 spelling)
...
051  $bad = = create ship: type=null owner=Player addto=$station x=null y=null z=null   * null tests the same failure as a bad type, without a fake name that would not compile (B15)
```

**Arguments to set in the editor:** `ware` (Argument) — any ware an NPC station sells near you, e.g. `Hydrogen`.

**Expected log lines (`log09999.txt`):**
```
T5 station found: <station name>
T5 create ship returned <ship or null/empty>
T5 exists=TRUE name=<name> maker=<race>      (or 'T5 exists=FALSE')
T5 docking allowed = TRUE/FALSE
T5 can transport Hydrogen = TRUE/FALSE
T5 max cargo Hydrogen = <number>
T5 bad type returned null                    (expected; anything else is a finding)
```

**How to run:** compile the script in-game (Script Editor → new script, paste source, add the `ware` argument), then start it with that ware as the argument while your ship is near an NPC station. Check `log09999.txt` in the game folder afterwards.

**Bad news for the drone approach (T5):**
- `create ship returned null` (or `exists=FALSE`) at a station where v8 already trades: the mechanism can silently fail mid-trade, confirming B15's need to null-check and retry with other types.
- `docking allowed = FALSE`: v8 never checked this; if a spawned ship cannot dock, its `buy`/`sell` return 0 and FDN wastes the whole trade cycle silently.
- `can transport ... = FALSE` or `max cargo = 0` for Hydrogen: the hardcoded TS type is not suited to common wares — Phase 2's runtime type resolution (REFERENCE §G step 4) becomes mandatory, not optional.
- Maker race is *not* Player/Argon-ish: the `owner=Player` parameter may be cosmetic; ownership and statistics behaviour would need re-testing before relying on it.

## 2) `tests/test.LI.FDN.T6.txt` — does destructing a docked drone fire SIGNAL_KILLED / show side effects

Full source in both files (T6 header + 001–031, handler header + 001–012). The load-bearing lines:

```
020   = $drone  ->  add secondary signal: SIGNAL_KILLED script=plugin.LI.FDN.T6.KillHandler    * VERIFY (B15)
023   $drone  ->  destruct: show no explosion=[TRUE]                                            (Sell.Ware L098 spelling)
...
029  write to log file 9999 append=[TRUE] value='T6 main script finished, check KillHandler line'
```

Handler (`plugin.LI.FDN.T6.KillHandler`): one log line, `return null`.

**Arguments to set in the editor:** T6: `ware` (Argument), e.g. `Hydrogen` — only used to find a station. Handler: none.

**Expected log lines:**
```
T6 drone docked at <station>, handler set
T6 SIGNAL_KILLED handler fired          <- may appear before, after, or never relative to the next line
T6 main script finished, check KillHandler line
```

**How to run (by hand):**
1. Open Statistics → **ships lost**, note the number (and total ships destroyed if shown).
2. Compile both scripts in-game; start T6 with `ware=Hydrogen`.
3. Watch the screen for ~5 s: any message, alarm or "ship destroyed" text?
4. Re-open Statistics → **ships lost**: same as before = good news; +1 = bad news (below).
5. Read `log09999.txt` and note whether `T6 SIGNAL_KILLED handler fired` appears at all, and before or after the "main script finished" line.

**Bad news for the drone approach (T6):**
- **Ships-lost counter goes up every trade.** v8 runs this destruct on *every* supply/sell cycle — that would inflate the player's lost-ships statistic permanently and could trip other mods' death handling. Most important number to read.
- **An on-screen message appears** (e.g. "ship destroyed"): visible noise every 25 s tick; FDN v9 would need a per-ship signal override or name-tag suppression (REFERENCE §G mitigation) — if no override command exists, document as known issue.
- **Handler fired:** good news for cooperating mods (they can skip tagged drones), but it confirms the engine treats the destruct as a real kill; anything reacting to player kills reacts to every FDN trade. If the handler *never* fires, secondary handlers cannot be used for that mitigation and only naming/tagging remains.
- **Handler line appears after "main script finished":** signals are queued, not synchronous — Phase 2 code must not assume side effects are visible immediately after `destruct`.
