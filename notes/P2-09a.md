# Card P2-09a — `plugin.LI.FDN.Supply.Factory.Check` on the shared libraries

Status: not tested. Header kept as `Tested: not tested`.

## What it does
The per-factory supply pass, now a forward round-robin budget loop driven by cursor `[13]` and budget `[22]`:
1. Loads settings via the standard `lib.LI.FDN.Cfg.Get` header (D1) and takes `$s.name = $script` once for Log calls (P2-01 lesson).
2. Reads the factory array from `[3]`; on null or empty it writes `$al.Settings[13] = 0` + `set global variable` and returns (defensive early return per Q1 — Supply.Start only calls this when `[3]` is truthy, but a standalone Script Editor start should not wedge).
3. Reads budget `[22]` with the same fallback-to-40 guard as Supply.Start L44-56 (T1: `is datatyp == DATATYPE_INT`, then `> 0`), persisting the fallback so later ticks read a real int.
4. Reads cursor `[13]`; out-of-range or invalid cursors reset to 0 (`$cursor >= $size.of.array` wraps, so an array that shrank since the last pass does not skip entries). Cursor and `$s = $cursor`, `$attempted = 0`.
5. Runs the while loop: `while $loop.active` where `$loop.active` is recomputed at the top and bottom of each body iteration with two separate `if`s (`$s < $size.of.array`, `$attempted < $factory.budget`) — no function calls in the condition, no AND/OR.
6. Per-factory: one call to `lib.LI.FDN.Is.Valid : obj=$factory need.dock=[FALSE]` covers exists + player ownership (B3). A non-TRUE result removes the entry at index `$s` in place, decrements `$size.of.array`, sets `$removed = [TRUE]`, and logs `' Clean from Factory Array'` via `lib.LI.FDN.Log`. The cursor does **not** advance and `$attempted` is not incremented (the next factory shifted into slot `$s`).
7. For a valid station, one call to `lib.LI.FDN.Is.Factory : station=$factory` catches docks / complex hubs that ended up in `[3]` (D10). Same removal path if it returns non-TRUE.
8. For a valid managed factory: one call to `lib.LI.FDN.Fac.Cfg : factory=$factory auto.manage=1` replaces the old get-or-create + first-seen block (D4; the pointer text id=4001 read moves into the lib). The two flags `[0]` and `[1]` are copied to `$manage.prod` / `$manage.res`.
9. Product branch (`if $manage.prod`): debug line via Log, then **synchronous** `= [THIS] -> call script plugin.LI.FDN.Supply.Factory : factory=$factory flag=1` (P4 — no START).
10. Resource branch (`if $manage.res`): re-check `$factory` via Is.Valid first (Supply.Factory may have waited and the station could be sold/destroyed), then run the `check.time == full.time` stall check or `< 45 s` near-completion check with flags; build `$txt.log` in a local before calling Log; synchronous call with `flag=null`.
11. After every wait: re-read `$enabled = $al.Settings[0]` and, if still enabled, validate the DC via `lib.LI.FDN.Is.Valid : obj=$dc need.dock=[TRUE]`; either failure sets `$loop.active = [FALSE]` (P4 / working rule 6).
12. After the loop: if `$s >= $size.of.array`, wrap to 0; write `[13] = $s` + `set global variable`. The run-lock `[12]` is **never touched** — Supply.Start owns both try and release via `lib.LI.FDN.Lock` (P2-08 coupling rule).

## Coupling with P2-08 (Supply.Start)
Satisfies the three coupling rules from P2-08:
1. No longer clears `[12]` on any exit — Supply.Start owns try and release via `lib.LI.FDN.Lock`.
2. Reads cursor `[13]` and budget `[22]` from `$al.Settings`, processes at most `[22]` valid factories per call starting at index `[13]`, writes the next cursor back to `[13]` (wrapping at `size of array [3]`).
3. Forward round-robin only — the v3 forward/backward toggle is gone; a budget larger than the array can never supply the same factory twice in one call because there is no in-loop wrap.

## Test steps
1. Fresh save, DC + ~5 factories, debug on → expected per tick: one `' Start Supply Called'` line; factory pass visits up to `[22]` factories with `' Supply Factory called flag = 1'` / resource-call lines for managed ones; `[13]` advances by the number of non-removed factories seen and wraps past `size - 1`.
2. Sell one factory mid-run → next visit: one `' Clean from Factory Array'` line, array shrinks in place, cursor does not skip a slot, `$attempted` unchanged for that entry.
3. Set `[22] = 2`, 5-factory array (P2-08 test step 4) → `[13]` increments by ≤2 per tick; all five visited within `ceil(5/2) = 3` ticks. No factory is supplied more than once in a single call even though budget 40 >> size 5.
4. Sell the DC mid-pass → first wait after which `$dc.valid` goes non-TRUE: no further `Supply.Factory` calls that pass; next tick `'DC invalid - cleared and paused'`.
5. Toggle debug off → no Log lines, but behaviour identical.

## Compiler rules followed
- No `!=`, no `AND`/`OR`, no `&&`/`||` — nested `if` / `if not` blocks only (the `$loop.active` flag is set by two separate ifs at top and bottom of the body).
- Leading `= ` on every `[THIS] -> call script …` statement that discards its return value, including every `lib.LI.FDN.Log` call.
- No inline `+` in any `call script` argument — `$txt.log = ' Check time = ' + $check.time + ' Full Time = ' + $full.time` is built in a local first.
- All array elements copied to locals before being used in conditions (T1: null comparisons are always FALSE).
- One-space-per-block indentation; no tabs. CRLF line endings preserved.
