# Card P2-11a - `plugin.LI.FDN.Buy.Ware` on the shared libraries

Status: tested TC 26/10/2026. Closes D1, D2 (one of nine), B4, B12, B15; owns the trade guard FDN.Trade.<ware> and counter [18] for buys.

## What it does
The buy half of the factory supply pass - Supply.Factory STARTs this script when a DC cannot cover a factory's resource requirement and the DC record allows buying for that ware:

1. Standard header via `lib.LI.FDN.Cfg.Get` (D1). `$PageID` is not fetched here; nothing downstream needs it because every debug line goes through `lib.LI.FDN.Log : text=... caller=$s.name` with `$s.name = = get script name`.
2. Guard chain, all ending in `goto label Exit:` so the buyer lock is released on every path:
   - `$factory.valid` initialised to `[FALSE]` before any guard (so a Cfg.Get failure or an early exit never touches the factory lock).
   - `Is.Valid : obj=$factory need.dock=[FALSE]` then `Is.Valid : obj=$dc need.dock=[TRUE]` (B12) - both results stored in locals, no inline `->` in conditions.
   - `Ware.Rec : station=$dc ware=$ware create=[FALSE]` (D3); a null record skips only this buy.
   - `$can.buy = $ware.settings[3]` kept from v8; if false, log "DC is not set to buy ..." and exit.
   - `$buy.at = $ware.settings[4]`; must be `DATATYPE_INT` (Trade re-checks it live against the partner price).
   - `$amount` INT and > 0 before anything counter-related runs.
3. Trade guard: `Lock : obj=$dc key='FDN.Trade.' + $ware action='try' timeout=120`. Set `$lock.held = [TRUE]` only on success; a held lock logs "trade guard held for ..." and exits (the 120 s stale covers a crashed prior run).
4. Task cap: fresh reads of `[18]/[19]`, nested INT checks (`is datatyp == DATATYPE_INT`) mirroring the Supply.Dock sell gate - non-INT or max <= 0 = unlimited; only while `active < max` does it increment `[18]`, save, and set `$counter.inc = [TRUE]`. A cap hit logs "trade task cap reached (active/max)" and exits with just the lock to release. A non-INT [18] (null in a save where Cleanup has not run) is counted from 0 before the increment.
5. Sector search: unchanged v8 behaviour - `lib.LI.FDN.Sectors : mode=3` (cache only, no scan); a null list means nothing is cached yet and skips this pass. Loop `while $s > 0` / `dec $s =` with the exact same find command as v8 L140 (`max.jumps=0`, `startsector=$sector`, `exclude array=$exclude.array`). Per found station: one wait-free `lib.LI.FDN.Trade : mode='buy' partner=$buy.Station ware=$ware amount=$amount home=$dc dest=$factory` (B15 - hardened drone, foe/price/money/space checks all inside Trade; returns units traded as INT >= 0). A non-INT result is floored to 0. `$traded > 0` decrements `$amount` and logs "Bought N of ware at station". `if not $amount > 0` sets `$s = 0` (no continue, no extra dec).
6. Between passes: `= wait randomly from 300 to 600 ms`, then re-validate factory and DC with `Is.Valid` again; either failure logs "Buy stopped - ..." and exits at the single label. After the loop, if `$amount > 0` log "No seller found for remaining N of ware".
7. Single `Exit:` label: release the trade guard (`Lock ... action='release' timeout=null`, no-op when not held), then decrement `[18]` (re-read settings via Cfg.Get first in case another task wrote them; floor at 0 so a stale counter can never go negative) and save, then `return null`.

## Test steps
1. Fresh save with DC + one factory whose resource requirement exceeds what the DC holds; set the DC record's can-buy [3] on and buy-at price [4] to a realistic number. Expected: Supply.Factory logs `Buy N of ware ... for <factory>`, STARTs Buy.Ware, which acquires FDN.Trade.<ware> on the DC (station local shows an integer playing time), increments [18], walks trade sectors; per found seller one `Bought X of <ware> at <station>` line. On Exit: the factory's own 'buy' lock is released immediately (no 120 s wait).
2. Force a second shortfall on the same ware right after a buy completes: Supply.Factory re-acquires its 'buy' lock and STARTs again; [18] caps out at [19] if it would exceed, logging `trade task cap reached`.
3. Destroy/sell the DC mid-run - after the wait, `Buy stopped - DC no longer valid`, Exit: releases both locks and decrements [18].
4. Ware with no record on the DC: one `Buy skipped - no FDN ware record for <ware>`; no trade guard taken, no counter change, factory 'buy' lock still released at Exit:.
