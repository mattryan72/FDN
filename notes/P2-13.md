P2-13: Format.Name and Sector.Array become thin wrappers

Closes
- D1 for plugin.LI.FDN.Format.Name and plugin.LI.FDN.Sector.Array (header via lib.LI.FDN.Cfg.Get)
- B10 for plugin.LI.FDN.Sector.Array (scan split out to plugin.LI.FDN.Scan, list return now reads the cache)

What changed
- Sector.Array: the v8 station scan, the factory/dock/exclude array filling and the sort are gone. Scan fills [3], [4] and [8] and builds the sector cache [15]. Sector.Array now reads the cache through lib.LI.FDN.Sectors (mode 1 + mode 2 joined for mode 4, or the requested mode otherwise) and returns the result sorted and reversed; if there is nothing it starts Scan once when no scan stamp sits in [16] and returns null.
- Format.Name: header now via lib.LI.FDN.Cfg.Get (page id from $al.Settings[1]); a guard returns null for a null or gone object instead of crashing on get name; output stays text 134 'name [ID]' exactly as v1/v8.

Behaviour kept
- Both script names and arguments are unchanged, so the menus keep calling them until P3 switches them to lib.LI.FDN.Sectors / lib.LI.FDN.Menu.ObjLine.
- Format.Name returns exactly text 134 'name [ID]' for a live object.
- Sector.Array returns a sorted, reversed array of sectors or null, as before.

Behaviour changed
- Sector.Array no longer scans and no longer writes [3], [4] or [8]. Supply.Start runs Scan every [17] seconds; the arrays are filled there now.
- If the cache was never built (no scan stamp in [16]) the first call starts Scan once and returns null, so a menu opened on a brand new save can show no sectors until Scan has finished.
- Modes 1, 2 and 3 go straight to lib.LI.FDN.Sectors modes 1, 2 and 3; any other value (the menus pass 4) returns factory sectors plus dock sectors joined - same as v8, because lib mode 4 would also add satellite sectors.
- Format.Name returns null for a null or gone object instead of crashing on get name.

Kept on purpose
- Format.Name does not use lib.LI.FDN.Menu.ObjLine: that lib does not exist yet and it adds the sector line; Phase 3 owns that switch, so this script keeps returning only 'name [ID]' (the v1 behaviour).
- The menus keep calling both scripts unchanged until P3.

Block count
- Sector.Array: 11 if + 1 while = 12 end, 2 gosub, 1 endsub (92 lines)
- Format.Name: 3 if = 3 end (40 lines)

Test plan hints
- Open the Factory list and Dock list menus and check the sector headings match before.
- Config.Menu and the details menus still show 'name [ID]'.
- A save with no scan stamp starts Scan once on the first Sector.Array call.
