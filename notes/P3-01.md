# P3-01 - Menu design note and new text IDs (page 9910, 300-399)

## Assumptions

- Main.Menu's `while [TRUE]` loop becomes the controller: each iteration builds one view from the top of a local stack array, opens it once, then hands the return value to plugin.LI.FDN.Menu.Command. No waits anywhere in this path (already true today).
- Five builder scripts exist: Menu.Station (builds BOTH the DC view and the Dock view), Menu.Stations, Menu.Factory.Details, Menu.Ware.Details, Config.Menu. Each returns an appended menu array; Main.Menu keeps only its heading (102) and footer.
- The stack is a LOCAL array in Main.Menu: array of [view, obj, ware]. No FDND.* globals. The updater token stays the settings index [20] already used since B8 - that is the only menu state stored outside locals.
- A killed controller cannot bump [20]; any _D updater left over exits when the next open bumps [20], which is exactly the stale rule B8 already relies on.
- Command strings and return-value shapes ([cmd, obj, ware, extra]) stay as in Reference E; nothing renamed.

## 1. View stack (local to Main.Menu)

    $stack = array of [view, obj, ware]   ; top is the last element
    token = $al.Settings[20]              ; int, already used since B8

One table for all views (v8 numbers kept so [5] and the _D scripts do not change):

| view | script                          | updater STARTed | obj                                   | ware  |
|------|---------------------------------|-----------------|---------------------------------------|-------|
| 1    | plugin.LI.FDN.Menu.Station      | DC.Details_D    | DC station                            | null  |
| 2    | plugin.LI.FDN.Menu.Stations     | none            | sector (from cache [15]) or null      | null  |
| 3    | RETIRED - unused                | none            | -                                     | -     |
| 4    | plugin.LI.FDN.Menu.Factory.Details | none         | factory                               | null  |
| 5    | plugin.LI.FDN.Menu.Station      | Dock.Details_D  | dock station                          | null  |
| 6    | plugin.LI.FDN.Menu.Ware.Details | none            | dock, or null for the DC              | ware  |
| 7    | plugin.LI.FDN.Config.Menu       | none            | null                                  | null  |

Menu.Station builds both view 1 and view 5; it checks the stack's view field to pick DC vs dock layout.
View 2 (Stations) replaces today's Factory list (old view 2) and Dock list (old view 3): sectors from cache [15], factories from [3], docks from [4]; AP/FL native groupings only, no TC-only rows.

Initial state on open: `[[1, $dc, null]]`. If no DC is set: `[[7, null, null]]` (same as today's L051-053).


## 2. Updater start rule (B8, moved into the controller)

The controller STARTs an updater and bumps [20] only when it ENTERS view 1 or 5 - i.e. the new top view differs from the one the current updater was started for ($updater.view local). Never on a redraw; never while already in that view with the same station. Builders never START anything, so the B8 blocks inside DC.Details.View.Sub / Dock.Details.View.Sub move up into this step.

## 3. Controller loop per iteration

1. `$top = $stack[size of array $stack - 1]` -> call its builder, append to $menu; set [5] = top view and save settings (unchanged meaning).
2. Footer: a Back row whenever the stack has more than one entry (any view, including 2 and 5); "Close" wording only when the top is the only entry (the bottom of the stack).
3. Open the menu once, get `$return`.
4. Call `plugin.LI.FDN.Menu.Command : stack=$stack  return=$return` -> returns the NEW stack or null to close. Main.Menu only assigns it back; it never edits the stack itself.

## 4. plugin.LI.FDN.Menu.Command (new script)

- Args: stack (Value/Array), return (Value). Returns the new stack, or null = close.
- New view -> push [view, obj, ware]. Back -> pop. set.dc -> replace the whole stack with [[1, $dc, null]] (merges old add.dc/change.dc per Reference E).
- Empty stack after a pop means close: return null. Main.Menu then runs plugin.LI.FDN.Cleanup and returns null.

## 5. Back / Escape

- The Back row is the array command ['back', null, null, null] (Reference E shape).
- `-1` (Escape) is treated exactly like 'back'. This removes today's whole L081-103 view-number cascade, which is the part most likely to desync after P1-05a added a third view.
- Only global actions return plain strings; everything else is an array [cmd, obj, ware, extra].

## 7. Things in the pasted scripts that do not fit the design (numbered)

Main.Menu:
1. L032-L034: $return / $called.by / $factory.show.array initialised before the loop - under the stack controller these are per-view state derived from the top of the stack, and leaving them across iterations is how stale values leak between views. Fixed by P3-05.
2. L081-L103: the -1 cascade (4 -> 2, 5 -> 3 or 2 via $dock.called.by, 6 -> $called.by, 7 -> 1) is replaced entirely by stack pop; 'back' and -1 do the same thing. The $dock.called.by special case disappears because "where you came from" IS the stack. Fixed by P3-05.
3. L094-L095: Back from Factory.Details hard-codes view 2; under the design it goes to whatever is on the stack (Stations or a Dock). Fixed by P3-05.
4. L172-L183 and L185, L189: open.factory / add.dc / change.dc / open.dock / open.ware set $menu.view inline or stash callers in bare globals ($dock.called.by, $called.by) - all of these return [view, obj, ware] from Menu.Command instead; Main.Menu never assigns views. add.dc + change.dc also merge into one set.dc per Reference E. Fixed by P3-04 (handlers) and P3-05 (controller no longer tracks views).
5. L195-L225: show.factory / show.type.dc / show.type.dock handlers - removed per Reference E (TC-only / replaced by nav rows); the $factory.show.array plumbing at L034 and L427-L433 goes with them. Fixed by P3-04/P3-05.
6. L254-L310: string commands handled in an else branch of "not array" - dynamic.dc / dynamic.dock / debug / auto become Toggle rows in Config built by the Toggle lib, so the controller has exactly two shapes to check (array vs plain-string global action). Fixed by P3-04 and P3-08c.
7. L317-L322 and L047-L049 / L556-L559: switch.menu and the header "Switch to:" row - removed; the next view is a normal nav row (open.stations). Fixed by P3-05.
8. B8 updater blocks inside DC.Details.View.Sub (L412) and Dock.Details.View.Sub (L446): builders must not START scripts; both move into the controller's "enter station view" step of section 2 above, and now also cover docks reached via Menu.Stations. Fixed by P3-05.

Command handling:
9. remove.ware must re-check stock == 0 (physical + virtual) before deleting a record - the UI only offers Remove at 0 stock but supply can land in between; on failure log and skip. Fixed by P3-04. (The B26 guard already in Remove.Ware.Sub stays.)

Config.Menu:
10. L071 / L102: get station array per redraw - fine for now, but the Stations view wants docks from cache [4]; Config's Add/Change DC lists should use the same source once lib.LI.FDN.Menu.ObjLine exists so both menus cannot disagree about what a dock is. Fixed by P3-08c.
11. L065 `return $menu` vs trailing L237 `return null`, and no Back row of its own - view 7 of the stack requires the shared 'back' command row, and the dead return should go in the rewrite. Fixed by P3-08c.

Ware.Details / Factory.Details: not pasted here; their fit with the design (Back rows, stock lines) to be checked in P3-08a/P3-08b.
