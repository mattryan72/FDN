# P4-04 - Upgrade v2 (v8.04 save to v9.01)

Date: 28/10/2026. Status: source written, not built or tested.

## Files
- source_readable/plugin.LI.FDN.Upgrade.txt (v2): the migration, wait-free.
- source_readable/plugin.LI.FDN.Upgrade.Records.txt (new): the B5 record migration, STARTed once by Upgrade.

## What runs when
Every init/reinit (idempotent): grow the settings array to 30 (copying every old entry), fill empty config slots, START Cleanup, call Setup.Keys if the array was grown.
Only while [14] is not an integer of 901 or more: steps 1 to 6 of the card (clear [12]/[13], index 2 in [6], validate DC, purge [3]/[4], create/prune/seed [29], stamp [14] = 901, START Upgrade.Records).

## Decisions made
- Defaults are filled on every run, only into slots that hold no integer, so a save already stamped 901 by the Phase 1 stub (Matt's dev save) also gets them. Values: [17] 300, [18] 0, [19] 4, [20] 0, [27] 5, [28] 1. [13] and [22] are left to Supply.Start, which already defaults them. [15], [16], [21] to [26] are left alone (Setup.Keys owns [21], [23], [24]).
- Setup runs before Upgrade, so on a v8 save Setup.Keys skips itself (array too small). Upgrade calls Setup.Keys after growing the array, so the hotkey appears on the first load.
- The migration of ware records is its own task because it loops over every ware on every registry station and waits. [14] is stamped before it is STARTed, so it cannot start twice. A started task is stored in the save and carries on after a load.
- Cleanup is STARTed here on every init/reinit, as the card says. The Cleanup header says the wiring is P4-05 (al.LI.FDN.event); P4-05 must not start it a second time.
- "Dock" test: only the DC must be a Dock (Is.Valid need.dock). [3], [4] and [29] are purged with need.dock false (exists and player owned), the conservative reading of "dead or non-player".
- The card's log text "FDN upgraded 8.04 -> 9.01" is written with "to" in the script, to keep an arrow out of a string literal.
- The DC logbook line needs a new text: 333 on page 9910, "FDN paused: choose a new Distribution Centre." Text 331 is a different message (Station Manager).

## Known limits
- Matt's own dev save is already stamped 901, so the B5 migration, DC check and purge do not run on it. They run on a real v8 save, or in the test with [14] cleared.
- The new array is a copy: a script that held the old array in a local during a reinit keeps writing to the old one.
- Upgrade.Records changes null to 0 in slot 7 whenever it runs; this is safe only because v9 never writes null there.

## VERIFY in game
- `get local variables: regular expression='^FDN\.Ware\.'` returns only the ware records (not FDN.Settings).
- A started task carries on across a save and load.
