P3-02: lib.LI.FDN.Menu.Row, lib.LI.FDN.Menu.Toggle, lib.LI.FDN.Menu.ObjLine (new)

Closes
- D5: the 4-column menu row and the ON/OFF toggle row (about 28 hand-built copies in Config.Menu, Ware.Details and Factory.Details)
- D6: the 'Name [ID]' + sector header line (6 copies)

What changed
- lib.LI.FDN.Menu.Row (menu, label, value, retval): builds [1, label, -1, value]. With a retval array it appends 'create new array, arguments=row, retval, null, null, null' and adds a section, as the v8 rows did. With a null retval it adds a plain info line (no section), as the v8 info rows did.
- lib.LI.FDN.Menu.Toggle (menu, label, bool, retval): reads text 148 (ON) when bool is true, otherwise 149 (OFF), then calls Menu.Row with that text as the value.
- lib.LI.FDN.Menu.ObjLine (menu, object): validates the object with lib.LI.FDN.Is.Valid (need.dock FALSE), takes the name from Format.Name, and adds the info row [1, name, -1, sector] followed by the blank ' ' line, as Ware.Details did.

Behaviour kept
- All three append to the caller's menu array in place (arrays are references) and always return null. They are wait-free and START nothing.
- The libraries read no text ids except 148/149 (Toggle); callers pass labels already read from the text file.
- Row and ObjLine do nothing when the menu is not an array; Toggle also does nothing when Cfg.Get returns null; ObjLine does nothing for a null, gone or non-station object.

Kept on purpose
- All arguments are typed Value so a null menu, retval or bool can be passed without a type error.
- The blank separator line is part of ObjLine, because every v8 header block was followed by it.
- Nothing is wired in yet: the menu scripts move onto these libraries in P3-05 to P3-08.

Block count
- Menu.Row: 2 if = 2 end
- Menu.Toggle: 3 if = 3 end
- Menu.ObjLine: 3 if = 3 end

Test plan hints
- A test script builds a small menu with Row (clickable and info), Toggle (ON and OFF), ObjLine (the DC, null, a gone object), checks the array grew by the expected number of entries, logs it, then opens the menu so the layout can be compared with Ware.Details.
