P2-12a: Update.Ware on the shared libraries
===========================================

Closes
------
D1, D2 (one of nine), D3, B2/B9 (via Ware.Rec), B29, B30.

What changed
------------
- Header switched to lib.LI.FDN.Cfg.Get ($PageID comes from $al.Settings[1]).
- Debug.Sub and Add.Ware.Sub deleted; the inline settings [29] registry block is gone - record get-or-create and registry add are owned by lib.LI.FDN.Ware.Rec (create path).
- Every debug line goes through lib.LI.FDN.Log with $s.name as caller, at: guard failures (ware / station datatype / station exists / unknown action), record created, add, remove.
- A newly created record is used directly from the Ware.Rec create return - no stale null read after creation (B30).
- Show.Ware.Sub kept: after a new record it does add 1 / add -1 of the ware so the ware shows on the dock.

Behaviour kept
--------------
- Add/remove arithmetic and all return values unchanged.
- 'create' on an existing record writes nothing (Ware.Rec never overwrites).

Behaviour changed
-----------------
- Unknown action now returns 0 instead of running the remove branch (action guard added; null for 'create', 0 otherwise stays as before).
- A Dock whose record cannot be created is treated like a non-Dock: add clamps to free space, remove takes physical only.
- A non-int [0] in the ware record counts as virtual stock 0.

Kept on purpose
---------------
- One $pointer sprintf (text 4000) for the write-back name - Ware.Rec reads and creates but cannot store a changed record.

Block count
-----------
40 if + 0 while = 40 end, no Exit label needed (no lock or counter).

Test plan hints
---------------
- 'create' on a dock with no record: record appears, ware shows on the dock, return null.
- Add 5 then remove 5 of a cheap ware at the DC: net zero in cargo bay and virtual stock.
- Remove more than exists: returns only what existed (virtual first, then physical).
- Unknown action: returns 0, no stock touched.
- Null ware: returns 0 with a log line.
