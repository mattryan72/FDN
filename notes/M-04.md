# M-04: Energy Cell cost and payment — test plan (28/10/2026)

Scripts under test: `lib.LI.FDN.Cost` and `lib.LI.FDN.Cost.Pay`.
Follows the same pattern as `test.LI.FDN.Hub`: each check writes a `TEST Cost ...` line to 9910 (debug) and 9911 (test), final line `TEST Cost: n/m PASS`.

## Prerequisites

- A valid DC set in [2] (any player Dock).
- Settings array grown to 40 (run Upgrade or fresh install).
- At least one factory or dock belonging to the DC (for leg tests).
- The DC should have some Energy Cells: virtual EC in `FDN.Ware.<Energy Cells>`[0], physical SS_WARE_ENERGY, or both. If neither is present checks 5–9 exercise the defer path instead — note it in the log.

## Checks

### 1. Cost: zero-unit transfer returns 0
- Call `$c = [THIS] -> call script lib.LI.FDN.Cost : from=$dc to=$fac units=0`.
- Expected: 0 (no cost, no error).
- Log: `TEST Cost 1: zero units = $c (expected 0)`.

### 2. Cost: single unit, known ware type
- Pick a ware with known per-unit volume (e.g. SS_WARE_ENERGY, vol=1), $units=1.
- Call the cost script. Expected: B × T × V × H / 1000^3 rounded up to whole EC (min 1 if any factor non-zero and vol > 0).
- Log: `TEST Cost 2a: 1 unit EC = $c`, then verify against hand-computed value from the constants at the top of lib.LI.FDN.Cost.

### 3. Cost: large unit count — no overflow
- Call with units=999,999,999 (near INT32 max) for a ware with volume=1.
- Expected: finite positive EC value, no crash or negative result.
- Log: `TEST Cost 3: 999M units = $c (finite, >0)`.

### 4. Cost: zero-volume ware returns 0
- Call with a ware whose SS volume is 0 (if available; otherwise skip and note).
- Expected: 0. Log: `TEST Cost 4: zero-vol ware = $c` or `SKIP`.

### 5. Pay: [33]=0 — free, returns TRUE, no FDN.Cost written
- Save current [33]. Set [33]=0. Ensure the payer DC has some EC available.
- Call `$ok = [THIS] -> call script lib.LI.FDN.Cost.Pay : payer=$dc served=$fac cost=100`.
- Expected: [TRUE], no FDN.Cost local created on $dc or $fac, no EC removed. Restore [33].
- Log: `TEST Cost 5a: off returns TRUE`, `TEST Cost 5b: FDN.Cost not written`.

### 6. Pay: cost > 0 with sufficient EC — virtual-first deduction
- Set [33]=1. Ensure $dc has >= 200 EC available (virtual + physical, above protect).
- Read the virtual EC count before: `$v.before = <FDN.Ware record>[0]`.
- Call with cost=100. Expected: [TRUE]. Virtual reduced by min(100, v.before); if v.before >= 100 then virtual = v.before - 100 and physical unchanged; else virtual = 0 and physical reduced by (100 - v.before).
- Verify FDN.Cost on $dc: [0] >= 100, [1] >= 1, [2] is playing time (not null).
- Log: `TEST Cost 6a: pay returns TRUE`, `6b: virtual after = <val>`, `6c: FDN.Cost[0] >= 100`.

### 7. Pay: protect level — EC never drops below floor
- Set the DC's EC stock to exactly its protect level (maintain or reserve floor, whichever is larger).
- Call with cost=999999. Expected: [FALSE], FDN.Cost[3] increased by 999999, log line written.
- Verify EC stock unchanged (still at protect level).
- Log: `TEST Cost 7a: defer returns FALSE`, `7b: EC unchanged`, `7c: deferred = <val>`.

### 8. Pay: peer fallback — payer short, network covers
- Requires >= 2 DCs in [30]. Set up: $dc1 has small avail (e.g. 50), $dc2 has large avail.
- Call with cost=100, payer=$dc1. Expected: [TRUE], $dc1 EC reduced by ~50, $dc2 EC reduced by ~50 (each above their own protect). FDN.Cost on both DCs updated; $dc1[0] += 100, $dc2[0] += 50.
- Log: `TEST Cost 8a: peer pay TRUE`, `8b: dc1 EC reduced`, `8c: dc2 EC reduced`.

### 9. Pay: network short — defer with full cost
- Set up: all DCs in [30] have avail < total cost (e.g. each has only protect-level EC).
- Call with cost=500. Expected: [FALSE], FDN.Cost[3] on payer += 500, log line: `Cost: deferred need 500 EC, <name> has <n>, network <m>`.
- Verify no DC's EC was reduced (all-or-nothing).
- Log: `TEST Cost 9a: network short FALSE`, `9b: deferred = <val>`, `9c: all EC unchanged`.

### 10. Pay: served station FDN.Cost updated
- After a successful payment where $served is a valid DATATYPE_STATION, verify the served station's FDN.Cost[0] was increased by cost and [1] incremented.
- Log: `TEST Cost 10a: served FDN.Cost[0] >= <val>`.

### 11. Pay: invalid payer — defer path
- Call with $payer = null (or a destroyed station reference).
- Expected: [FALSE], no crash, log line written (DC name shows 'n/a').
- Log: `TEST Cost 11a: invalid payer FALSE`.

### 12. Restore all changed settings and locals
- Restore [33] to its saved value. Clear any FDN.Cost test entries created during the run (set back to pre-test values or null). Restore [30] if modified for check 8.
- Log: `TEST Cost 12: restore OK`.

## Final line
`TEST Cost: <passed>/<total> PASS` — write to both 9910 and 9911 via lib.LI.FDN.Log with caller='test.LI.FDN.Cost.Pay'. If any check fails, log `TEST Cost FAIL: <check number>` and continue (do not abort).

## Notes for the test author
- All calls are synchronous `[THIS] -> call script`. No waits.
- Save/restore every setting you change; the test must leave the save clean.
- The FDN.Ware record for Energy Cells is read via `lib.LI.FDN.Ware.Rec : station=$dc ware=SS_WARE_ENERGY create=[FALSE]`. Element [0] = virtual EC, [1] = reserve, [2] = maintain.
- Protect level = max(record[2] if >0 else record[1] if >0 else 0, ceil(capacity x pct / 100)). The test script should compute this independently and log it for each check that depends on it.
- `get max amount of ware SS_WARE_ENERGY that can be stored in cargo bay` gives capacity. If the DC has no cargo bay slot for EC (returns null or 0), treat capacity as 0, floor = 0.
- The peer list comes from `lib.LI.FDN.Dc.List`. For check 8 you need to add a second DC to [30] first: append its station object, then run the test. Restore [30] afterwards.
- Hand-computed expected values for checks 2 and 6 should use the constants at the top of `lib.LI.FDN.Cost` ($c.B, $c.J, etc.) read from that file at test time — do not hard-code them in the test script.
