# Card P2-09b — `plugin.LI.FDN.Supply.Factory` on the shared libraries

Status: not tested. Header kept as `Tested: not tested`. Closes D1, D2 (one of nine), D3, B3, B11.

## What it does
The factory<->DC supply pass, now a **called routine** — Supply.Factory.Check (P2-09a) calls it synchronously (`= [THIS] -> call script … : factory=$factory flag=1` / `flag=null`), never STARTs it:
1. Standard header via `lib.LI.FDN.Cfg.Get` (D1); `$s.name = $script` once for Log calls; `$dc = $al.Settings[2]` and `$debug.on = $al.Settings[7]` copied to locals before any condition. The old `$PageID`, `$DebugID`, `$pointer.settings` (text 4001 read) and `$now` are deleted — nothing uses them after this change.
2. DC validation reduced to one call: `$dc.valid = [THIS] -> call script lib.LI.FDN.Is.Valid : obj=$dc need.dock=[TRUE]`. The three hand-rolled checks (exists / owner race / Dock class) and the `$dc.valid = [TRUE]` init are gone; `Is.Valid` returns null/FALSE on any failure so no non-TRUE value ever passes. While invalid: products stay at the factory, resource remove and buy are skipped — Supply.Start owns telling the player (B3).
3. Product branch (`if $flag == 1`, unchanged logic): amount in cargo → `Update.Ware` 'add' on DC → remove from factory only what was added; a null return still falls back to v8 behaviour (-full amount) until P2-12a makes 'add' return real amounts on every path (comment now says "Tighten after P2-12a").
4. Resource branch: `required = 3 × per-cycle − in cargo`, clamped to the cargo max, then **B31 clamp** `$required < 0 → 0` kept. Debug line only when not skipped and debug on.
5. Under `if $required > 0`: record read via one lib call `$ware.settings = [THIS] -> call script lib.LI.FDN.Ware.Rec : station=$dc ware=$ware create=[FALSE]` (D3) — the text 4000 sprintf, the `get local variable` and the `$have.record` flag are gone; null = no record → only this ware's buy is skipped.
6. Remove from DC via `Update.Ware`, add whatever came back to the factory (unchanged). On shortfall: debug 'Buy N of ware … for <factory>' line kept verbatim, then **B11 via Lock**: `$lock = [THIS] -> call script lib.LI.FDN.Lock : obj=$factory key='buy' action='try' timeout=120`. The whole manual busy-flag block (FDN.Settings `[3]` get/create/elapsed math) is replaced. Per Matt's correction: **no `is datatyp == DATATYPE_INT` test on the lock result** — `[FALSE]` is an integer too, so that would have started a buy for a busy factory. Plain `if $lock` → START Buy.Ware; plain `if not $lock` (held FALSE or bad input null) → one debug line 'Buy skipped - factory busy (buy lock held, stale after 120 s)' and no buy this pass. No release here — P2-11a owns it; the 120 s stale covers a crashed Buy.Ware.
7. All debug goes through `lib.LI.FDN.Log : text=$txt.log caller=$s.name` with leading `= `, `$txt.log` built in a local first (D2). Every existing message text is unchanged except the old 'busy for another N s' line, which became the single 'Buy skipped - factory busy' line. The only START left anywhere in this script is Buy.Ware itself.

## Test steps
1. Fresh save, DC + 2–3 factories with managed product and resource supply, debug on → expected per tick: `<factory> has N of <ware> to pass to DC`, `Remove N  of … from …` (product); `<factory> requires N  of <ware>`; no `Buy skipped` line while buys are free.
2. Force a shortfall with the ware record set to can-buy → first pass: one `Buy N of ware … for <factory>` then Buy.Ware runs; immediately re-trigger before it finishes (or within 120 s) → one `Buy skipped - factory busy (buy lock held, stale after 120 s)` and no second buy; the local `FDN.Busy.buy` on the factory holds an integer playing time.
3. Wait > 120 s with nothing buying → next shortfall starts a new buy (lock went stale).
4. Destroy/sell the DC mid-tick → product kept at factory (`DC invalid - product kept at …`), no resource remove or buy lines for that pass; FDN pauses via Supply.Start on the next tick.
5. Ware with no record on the DC: `Update.Ware` 'remove' still runs (returns 0) and no crash, no buy — remaining wares in the same factory are still processed.
