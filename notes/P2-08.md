# Card P2-08 — `plugin.LI.FDN.Supply.Start` on the shared libraries

Status: tested (TC 23/10/2026). Header kept as `Tested: TC 23/10/2026`.

## What it does
The AL Plugin timer entry point for the supply cycle. Each tick it:
1. Loads settings via the standard `lib.LI.FDN.Cfg.Get` header (D1) and takes `$s.name = $script` once for Log calls (P2-01 lesson).
2. Reads `[22]` factory budget with a fallback to 40 on null/unset/negative (T1 guards: `is datatyp == DATATYPE_INT`, then `> 0`); persists the fallback so later ticks read a real int.
3. Initialises `[13]` factory cursor to 0 when it is not a non-negative `DATATYPE_INT`.
4. Reads `[17]` scan interval with a fallback of 300 s (T1 guards) and `[16]` last-scan time.
5. STARTs `plugin.LI.FDN.Scan :` (no arguments — Scan stamps `[16]` itself, P2-06) only when `[16]` is null/non-int or older than `[17]` s. The old hard-coded 300 and the local write of `[16]` are gone.
6. `= wait 1000 ms`, then re-reads `[2]/[3]/[4]/[11]` from settings (Scan may have rewritten them; arrays are shared references but the locals we copy must reflect any change) and guards `[11]` against null/negative (T1).
7. Logs `' Start Supply Called'` via `lib.LI.FDN.Log` when `[7]` is on (D2 — replaces the old `gosub Debug.Sub`).
8. If no DC is set, returns silently (B3: the player is only told once, when a real DC first fails validation).
9. Validates the DC with one call to `lib.LI.FDN.Is.Valid : obj=$dc need.dock=[TRUE]` (replaces the three manual exists/owner/class checks); any non-TRUE result goes through the single `DC.Invalid:` sub which clears `[2]`, writes the logbook entry and logs `'DC invalid - cleared and paused'`.
10. If there is a factory array, acquires run-lock `[12]` via `lib.LI.FDN.Lock : obj=null key=12 action='try' timeout=[22]*4 s` (REFERENCE §A row 12: stale after `[22]×4` s, i.e. 160 s at the default budget of 40). On success it logs `'Factory Array found'`, calls `plugin.LI.FDN.Supply.Factory.Check :` **synchronously** (no START — P4), and releases the lock via `lib.LI.FDN.Lock … action='release' timeout=null`. On failure (lock still held) it logs `'Factory Check already running or recently started - skip'` and only the factory pass is skipped.
11. Dock pass: unchanged `[11]` counter logic — runs every 7th tick, `START Supply.Dock.Check :` (P2-10a will switch this to a synchronous call + its own Lock).

## Coupling with P2-09a (Supply.Factory.Check)
This card does **not** add arguments to `plugin.LI.FDN.Supply.Factory.Check` or wrap it in a loop — Factory.Check is itself the factory loop. For this change to work as planned, P2-09a must:
1. Stop clearing `[12]` on its exits (Supply.Start now owns both try and release via `lib.LI.FDN.Lock`).
2. Read cursor `[13]` and budget `[22]` from `$al.Settings` at the top of its loop, processing up to `[22]` factories per call starting at index `[13]`, and writing the next cursor back into `[13]` (wrapping at `size of array [3]`).
3. Drop the forward/backward toggle — plain round-robin forward is the P4 shape.

## Compiler rules followed
- No `!=` anywhere (`if not is datatyp[ … ] == DATATYPE_INT`).
- No inline `+` in any `call script` argument (Log calls pass a literal string).
- All array elements copied to locals before being used in conditions (T1: null comparisons are always FALSE — guarded with `is datatyp` first where the value can be null on an old save).
- One-space-per-block indentation; no tabs.
