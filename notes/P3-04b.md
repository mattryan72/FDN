# P3-04b - plugin.LI.FDN.DC.Change

Status: built, installed, passed in game on TC 27/10/2026 (test 7/7, run twice).

## What it is
`plugin.LI.FDN.DC.Change(old, new)` changes the Distribution Centre as one wait-free event.
It is the only writer of settings [2] besides Setup. Menu.Command set.dc calls it after the
player confirms. Returns 'ok', 'busy', 'invalid', 'same' or 'fl.managed'.

## Steps
1. Take the global lock on settings [12] (the key Supply.Start uses for the factory pass),
   timeout [22] * 4 seconds. Not acquired: return 'busy', nothing changed.
2. Validate: Is.Valid(new, need.dock=TRUE) else 'invalid'; old == new is 'same'; on FL
   ([23] == 3) Is.FL.Managed(new) is 'fl.managed' (the lib is a FALSE stub until P4-06).
3. Records: for the old DC, every factory in [3] and every dock in [4], loop the tradeable
   ware array and create the record on the new DC with Ware.Rec(create=TRUE) if it has none.
4. Policy copy (Q1.1: copy): only for records created in step 3, copy [1], [3], [4], [5], [6]
   from the old DC record of the same ware. Existing records on the new DC are never touched.
5. Old DC records: [1] = null, [3] = FALSE, [7] = 1 (Q1.2: surplus on). The old DC stays in [4].
6. Both stations are kept in [4]; [2] = new; Reg.Add(new); save the settings.
7. Log 'DC changed: old -> new; records created n, copied n' through lib.Log.
8. Release the lock (one path for every result), return the result.

## Decisions
- Factory products and resources come from the factory's tradeable ware array, the same
  command Supply.Dock uses on docks. No separate product/resource command is used.
- No player message text was added. The DC view shows the new DC straight away.
- Lock key 12 only covers the factory pass; the dock pass is not locked, which is safe
  because this script has no waits.
