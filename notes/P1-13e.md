# P1-13e: plugin.LI.FDN.Sort.Wares — B17 (Other ware group)

**Card:** `[B17] Sort wares by main type`
**File:** `source_readable/plugin.LI.FDN.Sort.Wares.txt`

## What was wrong

The maintype `if / else if` chain at old L051–L073 had no catch-all: any ware whose
maintype is not one of the 9 listed constants (`SSTYPE_LASER`, `SSTYPE_SHIELD`,
`SSTYPE_MISSILE`, `SSTYPE_W_ENERGY`, `SSTYPE_W_NATURAL`, `SSTYPE_W_BIO`,
`SSTYPE_W_FOOD`, `SSTYPE_W_MINERALS`, `SSTYPE_W_TECH`) was never appended to any
temp array, so it vanished from every FDN ware menu (DC Details, Dock Details, AP
variants).

## What was done

1. **Header** — `(v2, engine 50)`, `FDNv9` desc, B17 return-values note added after L013.
   Original Version line left untouched per convention.
2. **Allocation** — `$tOther.Array = = array alloc: size=0` added alongside the nine
   existing temp arrays (after L027 comment).
3. **Classification** — plain `else` appended to the end of the maintype chain
   (`append $ware to array $tOther.Array`) at nesting level 2/3, matching L070/L071.
4. **Sort** — `$tOther.Array` sorted and reversed like every other group (after L078 comment).
5. **Group key** — `$other.Array = = create new array, arguments=301, $tOther.Array, …`.
   The `[0]` element is what the four menu callers pass to `read text id=$main.type`,
   so the key must be the text ID: 301. (Ids 8–17 are the nine existing group headings;
   300 is B26's confirm-remove string, so 301 is next free for "Other Wares".) This
   script itself never reads text — it only stores the integer as `[0]`, and there is
   no `$PageID` in scope here.
6. **Append** — added *last*, after the final existing `append $laser.Array to array
   $main.ware.Array` (L122), guarded by `$tOther.size = size of array $tOther.Array` /
   `if $tOther.size > 0` / append / `end`. No empty heading when there are no
   unclassified wares.

## Text ID

Added to `src/t/9910-L044.xml` (page 9910), right after id=300:

```xml
<t id="301">Other Wares:</t>
```

## Conventions kept

- No renumbering: every pre-existing `NNN` prefix is untouched; all new lines are
  unprefixed (matches how P1-13a–d were applied).
- One-line conditions only; no `!=`; no compound tests.
- `$tOther.*` / `$other.Array` naming matches the existing `$tlaser.Array` /
  `$laser.Array` pattern.
