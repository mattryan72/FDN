# P1-10b: Menu.DC.Details_D (B8) - DC updater re-reads event global and exits on token change

Date: 2026-10-19 · Phase 1, branch `phase1-bugfix` (working tree on `main`)

## Script: plugin.LI.FDN.Menu.DC.Details_D (v1.0 -> v2)

### Assumptions
- The token in `[20]` is written by Main.Menu only when it STARTs a `_D` updater (P1-09a): one bump at menu open, and one per new updater. So "token changed since I started" reliably means an older updater must exit (B8). Same assumption as P1-10a.
- Re-reading `al.LI.FDN.event` each loop pass is the same pattern Main.Menu uses; it's cheap (one global read) versus a 1000-5000 ms wait.

NOTES_semantics was not pasted for this card, so it is unconfirmed whether a `START`ed task begins executing synchronously (first pass of the while loop including the write sub) before Main.Menu's call stack unwinds and draws view 1. Test step 2 below covers this; if it is observed, follow-up would be Main.Menu *calling* DC.Details_D synchronously once on entering view 1 (separate card).
