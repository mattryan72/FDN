# P2-05 - lib.LI.FDN.Lock (playing-time lock)

## Scope
Single synchronous, wait-free owner of the B1/B11 playing-time lock. Object locks live in a station local named `FDN.Busy.<key>` (text 4100); global locks (`obj = null`) live in a settings index given by `key` in `al.LI.FDN.event`. No waits, no START - callers use it to gate work (B1 supply run-lock [12], B11 Buy.Ware start-per-120-s). Trade guards `FDN.Trade.<ware>` (text 4101) are set by the trade task directly in P2-11a/b, not by this lib.

## Assumptions
- Settings [12] is a generic global-lock index here - no special case for the supply run-lock; callers pass the index they want. (Matt confirmed: generic `$al.Settings[$key]` with no [12] special case.)
- Global writes persist via `set global variable: name='al.LI.FDN.event' value=$al.Settings`, same idiom as Supply.Start L131-132 and Factory.Check's [12] clear.
- Stale boundary (Matt confirmed): `$elapsed < $timeout` = still held -> return FALSE; `$elapsed >= $timeout` = stale -> take the lock. So a lock exactly `timeout` seconds old is taken.
- Object locks require `obj` to be `DATATYPE_STATION` and `-> exists` before any read/write of its local (guard-before-dereference rule).

## Answers resolved
1. **Text 4100/4101** - Lock itself only uses 4100 (`FDN.Busy.%s`). Added both `<t id="4100">FDN.Busy.%s</t>` and `<t id="4101">FDN.Trade.%s</t>` right after `<t id="4005">` in `source_readable/9910-L044.xml` AND the mod build copy `src/t/9910-L044.xml` (same as 300/301 in Phase 1), so Lock can be tested in TC today with no ReadText collision.
2. **Global index** - generic `$al.Settings[$key]`, bounds-checked (`$key < 0` or `>= size of array $al.Settings` -> null). No [12] special case.
3. **Stale boundary** - `< timeout` held, `>= timeout` stale (see above).

## Changes
File: `source_readable/lib.LI.FDN.Lock.txt` (new, v1, engine 50)
- Header block in the standard FDNv9 lib format; contract documented in header comments.
- Fetches settings via `lib.LI.FDN.Cfg.Get`; returns null if FDN not initialised. `$key = [ARG] key` returned by value (no array element dereferenced).
- Lock-location resolution: object branch (`if $obj`) datatype-STATION guard + exists check, then `$pointer = sprintf` from text 4100 and read the local; global `else` branch bounds-checks an int `key` and copies `$al.Settings[$key]` to a local.
- Action dispatch is plain `if / else if / else` (no compound `||`, no bare `VERIFY:` line): `'try'` sets `$now = playing time` first, guards `timeout` (int + > 0), and takes the lock when free or stale; `'release'` clears to null and persists. Bad action -> null.
- Object writes use `$obj -> set local variable`; global writes use `$al.Settings[$key] = ...` + save global. No array element in any condition.

## Bugs fixed vs draft (per Matt)
1. `$now = playing time` moved to the top of `if $action == 'try'`, before `if is datatyp[ $lock.value ]...`; dropped the unused `$free`.
2. Guarded `$timeout` first (`is datatyp == DATATYPE_INT`, then `> 0`) inside try; stale test uses `$elapsed < $timeout` (the `$` was missing); only computes `$elapsed = $now - $lock.value` when `is datatyp[ $lock.value ] == DATATYPE_INT`.
3. Dropped the unused `$local.mode`; write/clear branches are plain `if $obj ... else`. Global branch also bounds-checks (`$key < 0`, `$key >= size of array`).
4. No compound `||` action check; second half is `if 'try' / else if 'release' / else return null`; the text-4100 dependency note is a `*` comment, not a bare `VERIFY:` line.

## Test (TC)
- Global: call with obj=null, key=21, action='try', timeout=5 -> TRUE; immediate second try -> FALSE; after 6 s of playing time -> TRUE (stale). release -> TRUE then next try -> TRUE again (was null).
- Object: pass a player station + key 'Test' -> sets local `FDN.Busy.Test`; second try -> FALSE until stale. Pass a non-station (e.g. a ware) or a destroyed object -> null, no crash. Bad action / out-of-range index -> null.
