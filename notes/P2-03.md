## What it does
Returns the station's ware record array (the 12-element local `FDN.Ware.<ware>`), or creates it with the old defaults plus `[8] = null` when `create` is true and no record exists. `create` false/null never writes anything. Bad input (settings missing, station not a DATATYPE_STATION or destroyed, ware null) returns null before any object command that could throw.

## Test steps
1) Fresh save, FDN initialised with a Dock as DC. Call `Ware.Rec(station=DC, ware=<any ware>, create=[FALSE])` -> expect null (no record yet), and confirm no `FDN.Ware.<ware>` local appears on the station.
2) Same call with `create=[TRUE]` -> expect a 12-element array back; `[0]=0`, `[3]=[FALSE]`, `[4]/[6]` = station price of the ware, `[5]=5=-1` (i.e. [5]=-1), `[7]=-1`, rest null. Re-read the local `FDN.Ware.<ware>` off the station and confirm it matches; also confirm no entry was added to registry `[29]` yet (that is P2-05b).
3) Call again with `create=[FALSE]` -> expect the same array returned, values unchanged.
4) Call a second time with `create=[TRUE]` after manually changing e.g. `[7]` to 1 -> expect the record returned untouched (still `[7]=1`, not reset to -1): get-or-create must never overwrite.
5) Bad input: station = null, or station = a number -> expect null; ware = null -> expect null. None of these may write anything.
